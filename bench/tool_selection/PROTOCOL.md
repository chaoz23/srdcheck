# Preregistered MCP tool-selection study

Status: preregistered design; no comparative results had been collected when
this file and `cases.jsonl` were committed.

## Decision

SRDCheck currently publishes one MCP tool per query. This study asks whether a
four-operation protocol (`capabilities`, `evaluate`, `enumerate`, `explain`)
improves an agent-DM's first call enough to justify changing that surface.
It does not authorize a production API change.

The primary user is an AI agent acting as the DM for human players, usually in
a Discord text channel. Every prompt therefore puts the subject in that role
and requires one immediate tool decision before narrating a ruling.

## Frozen arms

- `specialized`: the exact tools returned by SRDCheck's MCP `tools/list` at the
  tested commit. Adapter query schemas remain intact.
- `compact`: four virtual tools generated by the harness. `evaluate` and
  `enumerate` carry a `query_type` plus the same adapter-owned parameter object;
  `explain` performs source-heading lookup; `capabilities` describes supported
  queries. The compact arm is evaluated without shipping it.

The common lane contains adjudication and enumeration tasks both arms can
perform. The protocol-only lane contains discovery and source-explanation tasks
that the compact proposal adds. Protocol-only results are reported separately
and never blended into the head-to-head result.

## Cohorts and repetitions

Run one current model in each declared cohort:

1. frontier hosted;
2. mid-tier hosted;
3. local model small enough for realistic self-hosted AI-DM use.

Use temperature zero (or the closest supported setting) and two independent
replicates per case and arm. Record the exact provider/model identifier, date,
subject command or driver, SRDCheck commit, arm, case-set digest, and replicate.
Changing a model identifier after seeing results creates a new named study; it
does not replace the preregistered run.

## Prompt and execution

The harness serializes each arm's complete tool catalog, followed by one case,
and asks for exactly:

```json
{"tool": "tool_name_or_null", "arguments": {}}
```

This catalog-conditioned design is uniform across hosted and local models. It
measures discovery from the same metadata MCP clients receive, but it is not a
substitute for a native-client replication before any deprecation.

Every proposed call is then executed against the same SRDCheck engine. Gold
arguments include every supplied fact; exact argument preservation is required
so a superficially plausible verdict cannot hide dropped table state.

## Metrics

Report each metric separately by cohort, arm, lane, and replicate:

- selection success: correct first tool (or correct no-tool abstention);
- argument success: exact canonical arguments;
- execution success: the selected call executes and returns the frozen expected
  verdict/exit code where applicable;
- first-call success: all three conditions above;
- broken output: no parseable single call;
- catalog tool count and UTF-8 byte count; approximate tokens may be shown only
  as a clearly labeled estimate.

There is no weighted or composite score. The primary comparison is common-lane
first-call success. Catalog bytes are a cost measure, not a tie-breaker that can
erase accuracy regressions.

## Decision thresholds

- Adopt a compact production experiment only if it is non-inferior in every
  cohort on common-lane first-call success (no decrease greater than one case
  in either replicate) and improves the pooled common-lane result by at least
  10 percentage points or reduces catalog bytes by at least 60% with no cohort
  regression.
- Preserve any specialized schema whose cases outperform the compact arm by at
  least two calls within a cohort across the two replicates. Such a tool becomes
  an explicit exception, not an alias silently removed.
- Do not deprecate or alias any public tool from this prompt-conditioned study
  alone. A native MCP-client replication and at least one real AI-DM integration
  pilot are mandatory.
- If results are mixed, retain the current surface and improve descriptions or
  add opt-in compact aliases. Default-surface changes require new evidence.

## Surface budget and compatibility policy under test

The candidate default budget is six tools: the four compact operations plus at
most two evidence-backed specialized exceptions. Existing specialized names
would remain supported for the normal N/N-1 semantic window, be marked aliases
for at least one minor release before removal, and continue returning the same
structured verdict contract. This is a hypothesis, not current policy.

## Known limits

The cases are synthetic but table-shaped, use explicit facts, and do not measure
voice latency, client-specific tool rendering, multi-call repair quality, or
long-session context loss. They test first-call discovery and argument mapping,
not whether a model knows D&D rules without SRDCheck.
